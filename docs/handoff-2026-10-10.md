## 本次实现

Rust/Tauri 平台层已完成以下适配：

- 使用 `rfd` 提供跨平台原生文件选择器。
- 使用 `keyring` 的 macOS 和 Windows 原生后端保存模型 API Key。
- 非 macOS 使用 `hayro` 渲染 PDF 页面，并限制页数、尺寸和模型可接受的 PNG 大小。
- 预览目录改为 Tauri `app_local_data_dir`，禁止写入固定开发机路径。
- Windows 预览流程支持 Obsidian 注册表、退出等待、`obsidian://open` URI 和临时 Vault 清理。
- 预览文件路径检查 Windows 保留设备名、非法字符、尾部空格/句点，以及大小写不一致的重复路径。
- 批次写入、撤销、逻辑连接预览和预览清理共用同一目录校验。

前端和工程侧已完成以下适配：

- 预览根目录通过共享 Promise 加载，失败后可重试。
- 两种预览流程互斥，避免同时操作 Obsidian 临时 Vault。
- 前端构建改用 esbuild JavaScript API，避免 Windows 上执行 `.cmd` 的兼容问题。
- 新增 `.github/workflows/windows.yml`，在 Windows runner 上执行测试、Rust 检查并生成 MSI/NSIS 产物。
- README 已补充 Windows 开发环境、构建和隐私说明。

## Windows 接手验收

1. 在 GitHub Actions 的 `Windows desktop` workflow 中确认 `npm ci`、前端测试、TypeScript、lint、Cargo 测试和 `npm run desktop:build` 全部通过。
2. 下载 MSI 和 NSIS 产物，在 Windows 10/11 x64 上安装并启动。
3. 验证原生文件选择、Windows 凭据管理器 API Key 保存、文本和 PDF 导入、Hayro 页面渲染。
4. 使用 Obsidian 桌面版验证临时 Vault 注册、预览打开、URI 定位、确认写入、撤销和预览清理。
5. 检查包含 Windows 保留设备名、非法字符、大小写重复路径的批次会被拒绝，并且不会写入真实 Vault。

Windows 构建需要 Visual Studio Build Tools、WebView2、Rust MSVC target 和 Obsidian 桌面版。Windows 安装包输出位置为：

```text
src-tauri/target/release/bundle/msi/*.msi
src-tauri/target/release/bundle/nsis/*.exe
```
